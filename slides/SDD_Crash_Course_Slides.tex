\slideshell{02 / 36}{MODULE 01: SPECIFICATIONAL CODING}{Specificational Coding vs.\ Conversational ``Vibe Coding''}{Making source code a compiled artifact of a living, version-controlled specification}{
  \bcard{0}{0}{7.1}{3.9}{gbgred}{gred}{
    {\fontsize{15.5}{19}\selectfont\bfseries\textcolor{gred}{Anti-Pattern: Conversational Coding (``Vibe Coding'')}}\\[7pt]
    \textbf{1. Prompts Disappear After Merge:} Chat history vanishes when the session closes, leaving future engineers with code and zero recorded intent.\\[4pt]
    \textbf{2. Silent Edge-Case Guessing:} Agent guesses whether blank task titles are allowed or whether a 100\% full daily schedule should be rejected.\\[4pt]
    \textbf{3. Sycophantic Self-Testing:} Unconstrained prompts write weak assertions that rubber-stamp broken implementation code.\\[4pt]
    \textbf{4. Collateral Regressions:} Agent reverses note ordering while adding a feature.
  }
  \bcard{7.6}{0}{7.1}{3.9}{gbggreen}{ggreen}{
    {\fontsize{15.5}{19}\selectfont\bfseries\textcolor{ggreen}{Solution: Specificational Coding (SDD + SDT)}}\\[7pt]
    \textbf{1. Persistent Spec Artifact:} The user edits and approves \code{spec.md}; the agent compiles that spec into code (\textbf{SDD}) and 1:1 tests (\textbf{SDT}).\\[4pt]
    \textbf{2. Socratic Grilling Before Code:} Agent asks 3--5 targeted boundary questions before generating any specification or code.\\[4pt]
    \textbf{3. Surgical Scope \& Stack Locks:} Lock \code{Out of Scope} + \code{tech-stack.md}; verify at small Phase Checkpoints \& Stacked PR batches.\\[4pt]
    \textbf{4. Immutable Verifiers (\code{chmod -w}):} 1:1 \code{test\_reqXXXX\_*} + read-only tests.
  }

  \bcard{0}{-4.15}{14.7}{2.15}{gbggray}{gblue}{
    {\fontsize{14.5}{18}\selectfont\bfseries\textcolor{gblue}{Karpathy's 4 Coding Agent Rules (Enforced in \code{conductor/workflow.md})}}\\[5pt]
    $\bullet$ \textbf{(1) Think Before Coding:} Surface ambiguities via Socratic Q\&A instead of guessing $\cdot$ \textbf{(2) Simplicity First:} Write ~50 lines of clean stdlib Python instead of 500 lines of bloat $\cdot$ \textbf{(3) Surgical Changes:} Honor \code{Out of Scope} strictly $\cdot$ \textbf{(4) Goal-Driven Execution:} Loop against \code{test\_reqXXXX\_*} and \code{chmod -w} verifiers.
  }
}

    {\ttfamily\footnotesize
    "We are launching TaskFlow, a lightweight productivity app.\\
    For the MVP, build a Python TodoList class where users can\\
    add tasks, mark tasks as completed, list pending or completed\\

    }\\[8pt]
    \textbf{Why Vibe Coding Fails Here:} Without a spec, an agent guesses whether \code{"   "} is a valid task title, whether \code{complete\_task(999)} raises an error or returns \code{False}, and whether deleted IDs get reused!
  }
  \bcard{7.6}{0}{7.1}{4.0}{gbgblue}{gblue}{
    {\fontsize{15.5}{19}\selectfont\bfseries\textcolor{gblue}{Step 1 Action: Socratic Grilling ("The Grill")}}\\[6pt]
    In Plan Mode, the agent pauses and asks \textbf{3 Clarifying Questions}:\\[5pt]
    \textbf{Q1 (Blank \& Whitespace Titles):} Should \code{add\_task("  Buy milk  ")} trim whitespace, and what if the trimmed title is empty? $\to$ \emph{Trim whitespace; raise \code{ValueError} if empty.}\\[4pt]
    \textbf{Q2 (Missing Task IDs):} How should \code{complete\_task(id)} vs.\ \code{delete\_task(id)} handle unknown IDs? $\to$ \emph{\code{complete\_task} raises \code{KeyError}; \code{delete\_task} returns \code{bool} (\code{True}/\code{False}).}\\[4pt]
    \textbf{Q3 (Ordering):} How are filtered lists ordered? $\to$ \emph{Creation order (\code{id = 1, 2, ...}).}
  }

  \bcard{0}{-4.25}{14.7}{2.05}{gbggray}{gborder}{

1. Specificational Coding vs. Conversational Vibe Coding

Switch between the intuitive architectural metaphor and the exact Dual-Engine repository mechanics.

The Architect's Stamped Blueprint vs. Shouting Across a Job Site

Conversational Coding ("Vibe Coding") is like shouting renovation instructions across a noisy construction site: by afternoon, workers forget morning constraints, knock down load-bearing walls, and leave no blueprint behind. Specificational Coding (SDD) puts a git-versioned Blueprint between you and the AI builder: you grill edge cases upfront (The Grill), stamp numbered requirements (REQ-0001..0004), build with 1:1 tests (Apply), update the blueprint when discovering brownfield realities (Sync), and archive finished change orders (Clean).

Under the Hood: The Two-Plane Spec Engine + Phased TDD Harness

Conductor anchors repository-wide context in conductor/index.md (product.md, tech-stack.md, workflow.md) and executes phased Red-Green-Refactor TDD tracks (conductor/tracks/<id>/plan.md) with git notes audit trails. OpenSpec separates evergreen system truth (openspec/specs/<capability>/spec.md) from isolated work-in-progress proposals (openspec/changes/<id>/) validated via RFC 2119 keywords and 4-hashtag #### Scenario: blocks.

4. Common Practitioner Misconceptions (✕ vs. ✓)

Avoid the three most frequent traps when adopting Conductor and OpenSpec in production repositories.

✕ Misconception 1: "Plan Mode in my CLI is already Spec-Driven Development."
✓ Reality: Built-in Plan Mode is an ephemeral session scratchpad that vanishes when the chat closes. SDD persists git-versioned REQ-XXXX contracts in openspec/specs/ and conductor/tracks/ so future sessions and CI enforce them.
✕ Misconception 2: "A partial MODIFIED block in OpenSpec appends my new scenario."
✓ Reality: OpenSpec's delta merger replaces the entire requirement block on MODIFIED. Always copy the full existing requirement + all prior #### Scenario: blocks before adding your new scenario.
✕ Misconception 3: "Let the implementation agent edit failing tests so CI turns green."
✓ Reality: That triggers sycophantic self-testing. Lock contract tests read-only (chmod -w and Edit(**/adversarial_tests/**) deny rules in .claude/settings.json).

# Milestone 2 (M2 — Clearing & Account Statements) Design Spec
**Date:** 2026-10-02
**Status:** Implemented

## Overview
Extend `LedgerFlow` with pending transfer clearing (`settle_pending`) and chronological account statement generation (`account_statement`).

## Requirements & Design

### 1. Pending Transfer Settlement (`settle_pending`)
- **Signature:** `settle_pending(tx_id: str) -> dict`
- **Rules:**
  - Looks up `tx_id` in recorded transactions; raises `KeyError` if `tx_id` is unknown.
  - Verifies `status == 'PENDING'`; raises `ValueError` if the transfer is not currently in `'PENDING'` state (e.g., already `'SETTLED'`).
  - Transitions `status` to `'SETTLED'` and credits `amount_cents` to `to_acct`.
  - Returns a copy of the updated transaction dictionary.

### 2. Account Statement (`account_statement`)
- **Signature:** `account_statement(account_id: str) -> list[dict]`
- **Rules:**
  - Raises `KeyError` if `account_id` is unknown.
  - Filters all transfers where `from_acct == account_id` or `to_acct == account_id`.
  - Sorts matching transfers by `(timestamp, insertion_index)` ascending.
  - Returns shallow copies of the transfer dictionaries so caller mutations do not corrupt internal ledger state.

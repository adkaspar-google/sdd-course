# Milestone 3 (M3 — Requirement Rename & Tiered Fee Mutation) Design Spec
**Date:** 2026-10-03
**Status:** Implemented

## Overview
Update `LedgerFlow` for Milestone 3 product requirement mutations: status/method renames (`AWAITING_CLEARING` and `clear_transfer`), inclusive high-value clearing threshold (`>= 100000`), tiered platform fees with a 10-cent minimum floor, and replay-safe idempotency on `post_transfer`.

## Requirement Mutations & Additions

### 1. Status & Method Rename (`RENAMED`)
- High-value transfers now use status `'AWAITING_CLEARING'` instead of `'PENDING'`.
- `clear_transfer(tx_id: str) -> dict` replaces `settle_pending(tx_id)` as the primary method to transition an `'AWAITING_CLEARING'` transfer to `'SETTLED'` and credit `to_acct`.
- `settle_pending(tx_id: str) -> dict` is retained as a backward-compatible alias delegating to `clear_transfer(tx_id)`.

### 2. Threshold & Tiered Fee Mutation (`MODIFIED`)
- **Clearing Threshold:** Inclusive `amount_cents >= 100000` starts in `'AWAITING_CLEARING'`; `amount_cents < 100000` starts in `'SETTLED'`.
- **Tiered Platform Fee:**
  - If `amount_cents >= 100000`: `fee_cents = max(10, (amount_cents * 50) // 10000)` (50 bps = 0.5%).
  - If `amount_cents < 100000`: `fee_cents = max(10, amount_cents // 100)` (100 bps = 1.0%, 10-cent minimum floor).

### 3. Replay-Safe Idempotency (`ADDED`)
- If `post_transfer` is called with an existing `tx_id`:
  - If `(from_acct, to_acct, amount_cents)` matches the existing transfer, return a copy of the existing transfer dictionary without re-debiting or re-crediting or adding a duplicate statement entry.
  - If `(from_acct, to_acct, amount_cents)` differs from the existing transfer, raise `ValueError('Conflicting tx_id')`.
